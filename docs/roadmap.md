# NekoLang Roadmap

## 目标

NekoLang 是一个编译器项目。

- 输入：`.neko` 源程序
- 输出：二进制可执行文件
- 后端路线：LLVM IR + `clang` 链接

本路线图只围绕“把语言编译成可执行程序”展开，不引入解释执行路线。

## 当前状态

当前仓库已经具备这些能力：

- 词法分析、语法分析、AST 构建
- 符号表与四元式生成
- 基本语句：变量声明、赋值、条件、循环、输出、返回
- 一维数组声明、赋值、输出
- 函数定义、函数调用、作用域与返回值检查
- `bool` 类型与比较表达式
- 命令行参数读取与基础文件读写
- LLVM IR 生成
- 通过 `clang` 与 `runtime/runtime.c` 链接为可执行文件
- `check`、`build`、`run`、`llvm-ir` 等统一 CLI 命令入口

当前仍然存在的主要限制：

- 多文件构建和项目清单还未开始
- 运行时接口仍以基础标量类型为主
- 发布说明、平台说明和安装体验还不完整

## 工具链路线

NekoLang 最终应包含一个类似 `cargo` 的工具，但实现顺序应分层推进。

### 第一层：编译器前端 CLI

先提供统一的编译器命令入口，服务单文件或少量源文件的构建流程。

建议命令：

- `neko check main.neko`
- `neko build main.neko -o app`
- `neko run main.neko`
- `neko llvm-ir main.neko`
- `neko ast main.neko`

这一层的目标是统一编译器使用体验，而不是立即引入项目管理和依赖管理。

### 第二层：项目工具

在语言核心和编译链稳定后，再引入类似 `cargo` 的项目工具能力。

建议命令：

- `neko new hello`
- `neko init`
- `neko build`
- `neko run`
- `neko test`
- `neko clean`

这一层将引入：

- 项目目录约定
- 项目清单文件，例如 `Neko.toml`
- 多文件构建
- 构建模式，例如 `debug` 和 `release`
- 标准库和运行时的链接策略

### 第三层：完整工程化能力

当项目工具稳定后，再考虑更完整的工程能力：

- 文档生成
- 示例模板
- 发布流程
- 依赖管理

依赖管理不应早于项目清单和多文件构建，否则返工成本会很高。

## Phase 1: 冻结 v0.1 语言核心

目标：稳定语法、固定边界，避免开发过程中频繁漂移。

任务：

- 固定标准关键字与兼容别名策略
- 固定 v0.1 支持的数据类型和语句集合
- 明确不在 v0.1 内的特性
- 让 README、文法文档、测试用例保持一致

完成标准：

- 文档与实现对齐
- 新增功能不再反复改词法和主语法

## Phase 2: 完整函数能力

目标：让程序可以被拆分成可复用的函数，而不是只能把逻辑堆在 `begin` 块里。

任务：

- 设计并实现 `return`
- 完成函数参数与返回值的语义检查
- 完成函数作用域与局部变量规则
- 补全 LLVM 后端中的函数定义与调用
- 增加函数相关的端到端测试

完成标准：

- 函数在前端和 LLVM 后端都能完整工作
- 能写并编译多函数程序

当前状态：已完成

## Phase 3: 完善类型系统与语义检查

目标：提高程序表达能力，并让编译错误更早、更明确地暴露。

任务：

- 增加 `bool`
- 明确比较表达式和条件表达式的类型规则
- 完善数组元素类型检查
- 补充参数数量错误、类型不匹配、重复声明等错误信息
- 统一前端语义检查和后端可生成能力

完成标准：

- 类型错误能在语义分析阶段被稳定识别
- LLVM 后端不会因为前端放过了非法程序而崩溃

当前状态：基础部分已完成，后续仍可继续细化错误提示

## Phase 4: 可执行程序所需的运行时能力

目标：让 NekoLang 能写出真正有用的小工具程序。

任务：

- 支持命令行参数
- 支持基础文件读写
- 扩展 `runtime/runtime.c`，将通用运行时能力收敛到 C 层
- 明确运行时接口与对应的 LLVM 声明方式
- 增加使用文件和参数的示例程序

完成标准：

- 能写一个读文件、处理内容并输出结果的命令行工具
- 能写一个依赖命令行参数工作的可执行程序

当前状态：已完成基础版本

## Phase 5: 发布与工程化

目标：让项目具备稳定构建、演示和发布能力。

任务：

- 提供统一 CLI 体验，例如 `check`、`build`
- 将现有 `neko.py` 演进为稳定的命令入口
- 去掉写死的目标平台配置，改为合理推导或配置
- 完善依赖检查和错误提示
- 提供若干完整 demo
- 补充发布说明与平台限制说明

完成标准：

- 新用户按照 README 可以编译并运行示例
- 能稳定产出二进制可执行文件

当前状态：CLI 入口与目标平台推导已完成，发布说明仍待补齐

## Phase 6: 项目工具

目标：让 NekoLang 拥有类似 `cargo` 的项目级工作流。

任务：

- 设计项目目录结构
- 设计并实现 `Neko.toml`
- 支持 `neko new`、`neko init`
- 支持项目级 `build`、`run`、`test`
- 支持多文件编译与链接

完成标准：

- 用户可以创建、构建并运行一个标准 NekoLang 项目
- 项目工具不要求用户手工组织底层编译命令

## v0.1 建议范围

建议将首个明确版本控制在以下范围内：

- 类型：`int`、`float`、`char`、`bool`
- 语句：变量声明、赋值、条件、循环、函数、返回、输出
- 数据结构：一维数组
- 后端：生成 LLVM IR，并通过 `clang` 链接成可执行文件
- 运行时：输出、命令行参数、基础文件读写
- 工具链：统一 CLI 命令入口

## 暂不纳入路线的方向

这些方向当前不进入主路线：

- 解释执行
- REPL
- 包管理器
- 模块系统的大规模设计
- 高级优化器
- 垃圾回收

它们不是永远不能做，而是不应在 v0.1 之前分散主线精力。
